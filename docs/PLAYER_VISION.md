# เกมที่ผู้เล่นอยากสร้าง

อัปเดต 2026-10-03 เวลาไทย · ที่มา: คำขอและข้อแก้ไขของผู้ใช้ในบทสนทนา
เอกสารนี้เก็บความต้องการไว้ให้ผู้ทำงานรอบต่อไป ไม่ใช่การฝึกน้ำหนักโมเดล

## สิ่งที่ผู้ใช้ยืนยันแล้ว

- ต้องการเกม roguelike deckbuilding ที่ตัวเองอยากเล่น มีคอมโบ การตัดสินใจ
  และเนื้อหาหลากหลายให้ทดลองต่อได้ ไม่วัดคุณภาพจากจำนวนการ์ดอย่างเดียว
- ต้องติดตั้งเป็น **APK บน Android**; เกมเว็บไม่ใช่ผลลัพธ์หลักที่ขอ
- ใช้ **LoTM และ Circle of Inevitability** เป็นธีมหลัก ผู้ใช้ส่งนิยายจีนสองเรื่อง
  ให้ค้นออฟไลน์แล้ว แยกข้อมูลจากนิยายกับกติกาที่เราออกแบบใหม่
- ใช้ **CZN เป็นตัวอย่างการออกแบบและงานภาพ** ผู้ใช้ต้องการเห็นผลจากข้อมูลที่วิจัย
  ได้จริง รวมถึงภาพ ตัวละคร ฉากและการ์ด ไม่ใช่ส่งเพียงตารางจำนวนไฟล์
- เกมปัจจุบันมีข้อความและ placeholder มากเกินไป ผู้ใช้ต้องการผลที่สวย น่าเล่น
  และมีตัวละคร/ภาพประกอบจริง การเพิ่ม definitions อย่างเดียวไม่ตอบโจทย์นี้
- ต้องการบัญชี/เก็บข้อมูลผู้เล่นออนไลน์เมื่อทำได้ด้วยงบศูนย์หรือน้อยมาก
  โดยยังเล่นและเซฟในเครื่องได้
- ผู้ใช้เป็นผู้เล่นทั่วไป ไม่มีพื้นฐานเขียนโปรแกรมหรือศัพท์ออกแบบเกม
  อยากบอกความรู้สึกและความต้องการตามธรรมชาติ แล้วให้ทีมช่วยแปลงเป็นงานที่เห็นได้
- ไม่ต้องการออกคำสั่งหรืออธิบายความต้องการเดิมซ้ำ ให้รับช่วงจาก brief และผลก่อนหน้า
  ถ้ารายละเอียดขาด ให้เสนอสิ่งที่ดูและเปรียบเทียบได้ก่อนถามศัพท์เทคนิค
- คำขอเพิ่มเติม “ขอทั้งหมดเลย”: ต้องการผลวิจัยและทรัพยากรอ้างอิงที่มีทั้งหมด
  รวมถึงส่งออกทุก resource ที่ติดตั้งไว้ตาม manifest; ไม่จำกัดแค่ตัวอย่างชุดเล็ก

## สิ่งที่ยังเป็นข้อเสนอ / ยังไม่ได้เลือก

ข้อเสนอถัดไปคือทำ **ฉากต่อสู้ที่มีภาพ ตัวละครที่มีเอกลักษณ์ และการ์ดมีภาพประกอบ**
หนึ่งส่วนที่เล่นได้ พร้อมทางเลือกงานภาพที่เห็นความแตกต่างจริงก่อนขยายทั้งเกม
นี่เป็นวิธีทำงานที่เสนอ ไม่ใช่สไตล์ภาพที่ผู้ใช้อนุมัติแล้ว

ยังไม่ยืนยันสไตล์วาด 2D/3D/Live2D, ตัวละครหลัก, ภาษาในเกม, ระดับ spoiler,
กลุ่มผู้เล่นเป้าหมาย หรือทิศทางหน้าจอที่ผู้ใช้ต้องการ โครงการปัจจุบันใช้ landscape
แต่เป็นการตั้งค่าของ implementation ไม่ใช่ preference ที่ผู้ใช้เลือก

## ฐานที่มีจริง

เกม Godot ปัจจุบันมี 3 สาย, 54 การ์ด, 21 ศัตรู, 12 อีเวนต์, 12 relics,
3 องก์ / 12 การต่อสู้ และ debug APK 0.2.0 ตรวจ static APK กับการเล่น/UI บน Linux แล้ว
ยังไม่ใช่ผลทดสอบบนมือถือ Android จริง งานภาพใน APK ยังเป็น placeholder

ผลวิจัยส่วนตัวมี CZN **140 PNG และ SCSP/atlas 10 ชุด** ไม่ใช่ตัวละครเคลื่อนไหว
ที่ประกอบสำเร็จ ภาพ reference และนิยายอยู่ในพื้นที่ส่วนตัว ไม่เข้า Git/APK

## แปลงคำพูดเป็นผลที่ตรวจได้

| คำขอแบบผู้เล่น | ผลที่ต้องเกิดกับผู้เล่น | หลักฐานรับงานที่เห็นได้ |
|---|---|---|
| “มีแต่ตัวหนังสือ ดูไม่น่าเล่น” | เห็นบรรยากาศ ตัวละคร และสิ่งที่จะทำก่อนอ่านรายละเอียด | ภาพจากฉากต่อสู้ที่รันจริง มีภาพฉาก/ตัวละคร/การ์ดที่รวมในเกมแล้ว และข้อมูลตัดสินใจอ่านได้ |
| “อยากทดลองคอมโบได้เยอะ” | เลือกสำรับและเสี่ยงต่างกันจนผลการเล่นเปลี่ยน | ตัวอย่างคอมโบที่เล่นจริงอย่างน้อยสองแบบ พร้อมทางเลือกและผลที่ต่างกัน |
| “ไม่รู้ต้องสั่งยังไง” | ตัดสินใจจากผลที่ดูออก ไม่ต้องตั้ง specification เอง | เสนอทางเลือกภาพสั้น ๆ อธิบายความรู้สึกที่ต่างกัน บันทึกคำตอบ แล้วใช้ต่อในงานรอบหน้า |

ความสวยและความสนุกยังต้องประเมินจากงานที่เห็น/เล่นและ feedback ผู้ใช้
ผล tests ผ่านหรือจำนวนคอนเทนต์เพิ่มไม่ใช่หลักฐานว่าความต้องการเหล่านี้สำเร็จแล้ว
