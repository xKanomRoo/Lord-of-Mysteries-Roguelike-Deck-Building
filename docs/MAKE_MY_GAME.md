# บอกเกมที่อยากเล่นด้วยคำธรรมดา

คุณไม่ต้องเลือก engine เขียนโค้ด หรือตั้งกฎเกมทั้งหมดก่อนเริ่ม
บอกสิ่งที่ชอบ สิ่งที่ไม่ชอบ ความรู้สึกที่อยากได้ หรือสิ่งที่อยากทำในเกม
ทีมจะยึด [ความต้องการเดิม](PLAYER_VISION.md) และแปลงเป็นงานให้ดูหรือเล่นได้

พูดแบบนี้ได้เลย:

> ฉากยังโล่ง อยากให้เห็นตัวละครเด่น ๆ และบรรยากาศลึกลับกว่านี้

> อยากให้บางคอมโบรู้สึกเสี่ยงแต่ถ้าใช้ถูกจังหวะจะสะใจ

> การ์ดอ่านยาก อยากดูภาพแล้วพอรู้ว่าใบนี้ทำอะไร

> ชอบแบบที่สอง แต่ขอสีสว่างขึ้นและปุ่มไม่บังตัวละคร

> ทำต่อจากความต้องการเดิม ลองเสนอสิ่งที่จะทำให้เกมน่าเล่นขึ้นแล้วทำให้ดู

## ทีมจะทำอะไรให้

จะสรุปผลที่เข้าใจสั้น ๆ เช่น “ทำฉากให้ตัวละครเด่น ลดข้อความที่เห็นพร้อมกัน
และยังอ่าน cost/เจตนาศัตรูได้” แล้วลงมือ งานย่อยแบ่งให้ด้านภาพ การเล่น เนื้อเรื่อง
การพัฒนาและการตรวจตามความจำเป็น โดยใช้ [skills ของทีม](AGENT_TEAM.md)

หากคำว่า “สวย” ยังตีความได้หลายแบบ ทีมจะทำตัวอย่างที่ต่างกันให้เทียบ
คุณตอบว่า “ชอบแบบนี้” หรือ “ไม่ชอบตรงนี้” ได้ ไม่ต้องอธิบายศัพท์ศิลปะ
ตัวอย่างระบุว่าเป็น concept หรือเกมที่รันจริง เมื่อขอเปลี่ยนเกม
ต้องมีภาพจากเกมหลังรวมงานและ APK ที่สร้างใหม่ตามส่วนที่เปลี่ยน

ทีมจำสิ่งที่ตกลงไว้ในไฟล์ของโครงการ หากเปลี่ยนใจบอกได้ เช่น
“ต่อไปอยากให้การ์ดมีภาพใหญ่กว่าเดิม” แล้วผู้ประสานแก้ข้อตกลงให้ทุกคนใช้ต่อ
เมื่อเปิด task ใหม่ใน repository นี้ Codex อ่าน `AGENTS.md` และความจำก่อนเริ่ม
คำสั่ง `$dream-game-director` เป็นชื่อ skill ใน repo ถ้า runtime รองรับค้น skills
หรือใช้คำธรรมดาว่า “ใช้ทีมจาก AGENTS.md ทำต่อจากความต้องการเดิม” ได้

## ขอบเขตที่ตรงไปตรงมา

skills ช่วยให้ทำงานเป็นระบบและจำข้อตกลงเมื่ออ่าน repository ไม่ได้ทำให้ AI
อ่านใจหรือรู้ความชอบทุกข้อ สิ่งที่ยังไม่เลือกจะเป็นข้อเสนอให้ดูและแก้ไขได้
การเพิ่ม skill files ไม่ทำให้เกมสวยขึ้นเอง ต้องทำ artwork รวมในเกมและตรวจผลจริง
